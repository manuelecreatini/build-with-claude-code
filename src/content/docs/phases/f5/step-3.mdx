<WhyThisStep>Some things only you can do: decide, pay, create an account, paste a secret. Making Claude stop explicitly keeps those moments visible instead of guessed.</WhyThisStep>

Claude must stop every time something is needed that only you can do or decide:

- a product decision;
- a credential or <Term id="api">API</Term> key;
- creating an account;
- a payment or a paid plan;
- an external configuration (<Term id="dns">DNS</Term>, OAuth app, <Term id="webhook">webhook</Term>[^31]);
- a legal text;
- a test on a real device.

**The protocol.** Claude prints a `HUMAN ACTION REQUIRED` block (template T9) with what is needed, why, the exact steps, how to verify, time and cost, and what it will do in the meantime. You carry it out and reply "done" (or choose an option); Claude verifies and carries on. It doesn't make up values and doesn't carry on with silent placeholders.

:::caution[Secrets: the rule with no exceptions]
Never paste keys or passwords into the chat. Enter them yourself in the `.env.local` file (open in VS Code) or in the service's dashboard. Claude knows only the variable *names*, from `.env.example`; the `deny` rules in `.claude/settings.json` stop it from reading the files with the values.
:::

**Useful tools in this step**

- `/wizard` <Role as="pocock" />: for long configurations it generates an interactive Bash walkthrough that guides you step by step (credentials, CI <Term id="secret">secrets</Term>, external service dashboards). On Windows run it in <Term id="git-github">Git</Term> Bash.
- `/to-questionnaire` <Role as="pocock" />: turns a decision you can't take on your own (partner, client, advisor) into a <Term id="markdown">Markdown</Term> questionnaire to send.
- `/wait-what` <Role as="pocock" /> and `/teach` <Role as="pocock" />: the first re-explains in plain words a message you didn't understand; the second teaches you a concept over several sessions.
- If the action can't be done right away, Claude labels the <Term id="issue">issue</Term> `ready-for-human`, comments on what is missing and moves to another unblocked phase.

[^31]: **Webhook**: an automatic notification that an external service (for example Stripe after a payment) sends to your application by calling one of its web addresses.
